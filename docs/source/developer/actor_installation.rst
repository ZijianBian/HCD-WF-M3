Building actors
===============

Physics actors are built from separate repositories and are not installed
by ``pip install`` of HCD-WF. Use an existing compatible installation when
available. Building an actor requires access to its repository, its
compiler and library dependencies, and the intended IMAS DD version.
See :doc:`../reference/actors` for the actor catalog.

iWrap actors
------------

Legacy and Hybrid use Python actors generated by iWrap. The
``actor_install/`` directory contains a build script and per-actor YAML
recipes, including ``torbeam.yml``, ``cyrano.yml``, ``fopla.yml`` and
``hcd_mergers.yml``. Each recipe specifies:

* ``SOURCES``: repository, revision and checkout directory;
* ``MODULES``: environment modules used for that build;
* ``BUILDS``: library build commands;
* ``ACTORS``: wrapper generation or installation commands.

Read the chosen recipe before building. Its module names and make targets
belong to that actor's build system; a recipe using default modules does
not guarantee a DD4-compatible build. For an already prepared compiler,
IMAS and iWrap environment, an invocation from the HCD-WF root is:

.. code-block:: bash

   python actor_install/actor_install.py \
       --skipModules --workDir /path/to/actor-build \
       actor_install/torbeam.yml

``--skipModules`` preserves the loaded modules, so load all dependencies
required by the recipe first. The SDCC workflow helper configures runtime
dependencies; it does not supply every actor's build tools. Installation
paths are controlled by the recipe's commands and actor build system.

For a rebuild, reuse the same ``--workDir`` with ``--skipSources``.
``--skipBuilds`` and ``--skipActors`` omit their respective stages;
``--checkRevision`` checks the source revision. Run the script with
``--help`` for the remaining options. It writes ``RELEASE.yaml`` in the
invocation directory; retain that build record locally.

Select a local actor installation before sourcing the workflow helper:

.. code-block:: bash

   export ACTOR_FOLDER=/path/to/PYTHON_ACTORS
   source config_hcd_iter_sdcc.sh

The helper adds this directory to ``PYTHONPATH``. Ensure it contains the
generated Python actor packages needed by the selected configuration.

Native MUSCLE3 actors
---------------------

Pure mode needs native actor executables. The iWrap recipes above do not
provide a general native MUSCLE3 build procedure; follow each actor's own
build instructions. The supplied Pure setup expects these executable paths:

.. code-block:: text

   $ACTOR_FOLDER/torbeam/torbeam_m3.exe
   $ACTOR_FOLDER/cyrano/cyrano_m3.exe
   $ACTOR_FOLDER/fopla/fopla_m3.exe
   $ACTOR_FOLDER/rabbit/rabbit_m3.exe
   $ACTOR_FOLDER/merge_waves/merge_waves_m3.exe
   $ACTOR_FOLDER/hcd2core_sources/hcd2core_sources_m3.exe

Install the actors selected in the saved configuration; the launcher removes
unused components from the generated topology. Use matching DD and MUSCLE3
versions across communicating actors. The SDCC helper and supplied templates
target DD 4.1.0 and MUSCLE3 0.8.0. The native FoPla executable is separate
from the iWrap ``fopla.yml`` recipe.

Rabbit's ``rabbit_impl`` in ``pure.ymmsl`` calls ``scripts/run_rabbit_m3.sh``.
This script selects the GCC/foss-2023b runtime in Rabbit's own process,
separate from the Intel actors. It expects IMAS-Fortran 5.5.0 with DD 4.1.0
and MUSCLE3 0.8.0. There is no Rabbit build recipe in ``actor_install/``;
obtain the compatible binary or build it in the Rabbit repository.

A custom yMMSL implementation can use the same script:

.. code-block:: yaml

   executable: bash
   args: ["/absolute/path/to/HCD-WF/scripts/run_rabbit_m3.sh"]

The GUI and ``run.sh`` convert the repository-relative
``scripts/run_rabbit_m3.sh`` argument to an absolute path in the generated
topology. When starting MUSCLE3 Manager directly, use an absolute script path.

The workflow checks configuration consistency before launch, but it cannot
establish binary compatibility from a file name. Confirm the build stack
and exercise a short case before a production run.
