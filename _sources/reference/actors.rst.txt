===============

Each row starts at index ``1``; index ``0`` disables the process. A saved
configuration's own ``list`` attribute remains authoritative.

Selection does not install an actor. Legacy and Hybrid need the selected
iWrap actors importable in the active Python environment, together with the
merge actors. Pure needs the native MUSCLE3 executables required by its
topology. See :doc:`../user/installation` and :doc:`available_modules` for setup.

Pure actor sets
---------------

The supplied Pure topologies support Torbeam and Cyrano with ``merge_waves``
and ``hcd2core_sources``. ``pure_rabbit.ymmsl`` adds Rabbit;
``pure_fopla.ymmsl`` adds FoPla. Rabbit and FoPla cannot be selected together in
a Pure topology. The launcher checks that the topology matches the XML actor
selection before starting. See :doc:`../user/execution_modes` for the mapping.

Parameters and dependencies
---------------------------

Actor parameter files use ``CATEGORY/PROCESS/input_ACTOR.xml`` beneath the
configuration directory. The GUI's code-parameter editor uses the actor's XSD
when supplied, including its field descriptions and validation rules. Keep
actor-specific physics settings with those files.

Legacy and Hybrid use the prerequisites and execution orders in
``hcdworkflow/global_configuration/global_lists.yaml``. For example, the EC
Fokker–Planck process requires an EC wave solver, and RISK requires an NBI
source. FoPla's configured prerequisite is an IC wave solver; the NBI
prerequisite lines are comments, not active requirements. Physical input
requirements still depend on the selected actor and case.

The four registered merge actors are ``merge_waves``, ``merge_distributions``,
``merge_distribution_sources`` and ``merge_core_sources``. They combine the
corresponding IDS outputs; the user selects the physics actors and
post-processing in the workflow XML.
