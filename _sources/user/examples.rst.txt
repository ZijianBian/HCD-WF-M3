Common case changes
===================

Start from a saved case whose input database and actors are available in your
environment. The examples below change that case; they are not complete
physics input datasets.

Run one time slice
------------------

In ``workflow_parameters``, set ``tbegin`` to the required time,
``one_time_slice`` to ``1``, and keep a positive ``dt_required``.
Run the case through its usual launcher:

.. code-block:: bash

   ./run.sh legacy /path/to/config

The standalone Legacy, Hybrid and Pure drivers use these settings. For an
externally driven Hybrid component, the controller supplies the time.

Extend to a time loop
---------------------

Set ``one_time_slice=0``, then choose ``tbegin``, ``tend`` and
``dt_required``. The end time is exclusive: for example, 10 to 40 s with
a 10 s step evaluates 10, 20 and 30 s.

Check that the input scenario and waveforms cover the interval, and choose a
new output run before launching. See :doc:`../reference/configuration` for
the time and output fields.

Add Rabbit to a Pure case
-------------------------

For a case already using TORBEAM, CYRANO and source mapping, select Rabbit
as ``nbi_fp``, supply its parameter files and NBI inputs, then launch:

.. code-block:: bash

   ./run.sh pure /path/to/config topologies/pure_rabbit.ymmsl

Rabbit needs the separate actor build described in
:doc:`../developer/actor_installation`. It advances on every time slice,
including intervals with zero launched NBI power.

This topology provides Rabbit outputs to post-processing. Selecting it does
not establish NBI-to-ICRH feedback: Pure schedules CYRANO before Rabbit, and
does not support Rabbit and FoPla together.
